## 完整流程

1. `python <SKILL_DIR>/scripts/paper_reader.py --workspace <WORKSPACE> import /绝对路径/文献.pdf`（也支持 UTF-8 Markdown、`.txt`、本地 `.html`/`.htm`、`.docx`、单文件 `.tex`）。结果为 JSON，记住 `document_id`。原件复制后按 SHA-256 校验；同一内容重复导入返回同一文档。CLI 导入 Markdown/HTML 可复制同目录内的本地图像（从不抓取远程 URL）；网页上传不含其相邻文件，缺图会阻止完成。HTML 是本地存档解析，不是站点爬取。TeX 仅处理当前单文件，不展开 `\input`/`\include`，也不编译；`\includegraphics` 记为未嵌入问题。DOCX 提取段落/标题/表格，复杂版式（文本框、页眉页脚、嵌入对象）支持有限。Word.Picture.8 的 VML EMF 预览在本机 PATH 有 rsvg-convert 或 inkscape，且 fontconfig 能提供 Times New Roman 替代和 OpenSymbol 时，经 GDI 回放转为 PNG/SVG；保真检查通过才作为图块显示并写下处理结果，否则保留 EMF 且问题保持未解决。`doctor` 用 `emf_preview` 报告这项，不因此判定 PDF 环境失败。
2. `python <SKILL_DIR>/scripts/paper_reader.py --workspace <WORKSPACE> show ID` 阅读**投影**，不要直接打开 `document.json`。结构阶段默认投影含 document_id、revision、stage、title、fingerprint、块数、atom 数、标题大纲（id + 文本摘要）、`issue_summary`（按 issue id 前缀或 type 的未解决/已解决计数和少量样例 id），以及每块摘要：id、kind、约 160 个码点的 text、是否已有 structure_note、source_ids 数量。不含 translation、history 或整份 atoms，也不含问题正文。`tasks ID` 在结构阶段同样只给一批块摘要和问题汇总。`progress ID` 默认是校验摘要的短投影（`projection: true`）：含 `ok`、非重复的结构性 `errors`、`error_summary`（大量 `missing translation` / `second-pass review required` 及同类 `missing …` 块错误收成计数和最多约 5 个样例）、`pending_translate` / `pending_review`、块计数、大纲长度和未解决 issue 数；已知限制只给 `confirmed_limitations_summary`（按类计数、最多 3 个样例 id、一条短 resolution）和压缩后的 warnings，不展开每条 `confirmed_limitations` 或逐条限制 warning，也不返回全量文档。完整错误列表和逐条已知限制用 `progress ID --full` 或 `validate`。只有必须核对 atoms、全文字符或全部译文哈希时才加 `--full`（`show --full` 与旧版一样返回整份文档、fingerprint 和 translation_hash）。结构调整前仍要查看原文页图，正文阅读顺序由你确认，不能盲信几何提取。合并断行/跨页、整理单双栏、标记标题、图注、公式、图表、参考文献与重复页眉。每个 atom 必须且只能被一个块引用；不要删除来源。改变源文字须给与本次改动对应的 `source_change` 解释（增量再次改文时不能沿用旧理由）。合并带图块时若会丢图须显式给出合并后的 `asset`（文档目录内已存在的非空文件名；`null`、空字符串或只提供该字段无效）。复杂公式/图表用 `crop ID --page N --bbox x0 top x1 bottom` 保存区域，再在结构块关联返回的 asset。整页备份不能取代正文核对。PDF 可选运行 `structure-candidates ID [--preview 预览.md]` 获取按坐标、栏位和行间空隙生成的段落候选与阅读顺序建议（写到 `WORKSPACE/candidates/`，见 [结构候选](structure-candidates.md)）。它只读：不改 `document.json`、revision 或复核状态，不生成或提交 payload。优先看带 `hard_spots` 的候选；上标数字脚注等已知限制须靠页图判断。不运行它，流程照常。
3. 通过 `submit ID payload.json` 提交 `structure`。两条路径兼容：payload 含完整 `blocks` 且覆盖全部 atoms 时，行为与以前一致；不传 `blocks` 而设 `keep_extracted: true`（或 `mode` 为 `keep` / `patch`）时，以当前提取块为起点，接受 `updates`（按 id 改 kind/text/source_ids/structure_note/asset/source_change；改 text/source_ids 须带本次 source_change）、`merges`（`into` + `from`，并入 source_ids 并删除 from 块，必须写 structure_note；多图合并须显式给出已存在的非空本地 asset 文件名，`null` 或空字符串无效）和可选 `default_structure_note`（给仍无说明的块填同一理由）。显式 updates/merges 的 structure_note 优先于默认说明。最终仍要求每块有非空 structure_note、atoms 精确分区一次、kind 合法。翻译或笔记产生后结构冻结。处理不可靠来源，用 `resolve` 说明解决方法或残留读限。预期限制（TeX 不编译插图、不展开 `\input`、HTML/Markdown 远程或缺图、DOCX OLE/oMath/缺图等）可按类提交 `limitations`（category + 非空 resolution + 本次核对 evidence）；`page` / `docx-sym` 这类无法识读正文禁止按类批处理。扫描页没有 OCR，不能凭空补全文。无法看清的正文须保留未解决状态或逐条写明检查结果，不能仅写“忽略”完成任务，也不能清空 issues 或提交空 resolution。按类解决只去掉“未解决”错误，并不表示资源已经补上。若随后用逐条 `issues` 改写某条 resolution，该条的 `resolution_evidence` 与 `resolved_by` 会被清掉，不再算批处理残留。
4. 全文结构读完后提交 `terms`：专业术语英文、中文及解释。没有专业词也须显式提交空列表。概念统一后，`tasks ID` 默认获取 16 个待办（`--limit` 可改，`show` 在翻译/复核阶段用同一默认）及目录、术语、相邻 `context` 和所属章节窗口；`--limit` 只限制待办数量，`context` 按邻接范围返回，章节过长时默认 `section_context` 最多约 24 块并返回 `section_window`。翻译/复核/术语阶段本批 `blocks` 含 `id`、`kind`、`text`、`source_ids`、`asset`、`translation`、`translation_hash`、`review`、`user_edited`、`has_structure_note`；`context` / `section_context` 里已出现在本批的块只是 `{"id","ref":true}` 引用壳，未进本批的邻居仍是完整投影。默认不含 `history` 和长 `structure_note`；不附带整份 atoms，issues 只给未解决摘要。`--full` 不去重。需要 history 或旧的全量 tasks 时用 `tasks ID --full`，或用 `--section-offset` / `--section-limit` 分段读取章节，不要一次吞整章。
5. 由你翻译并提供语义对齐，允许一对多、多对一及非连续片段。`pairs` 的字符偏移以 Unicode 码点计算（Python `len`），不是 JS UTF-16。每侧所有非空白字符必须准确覆盖一次。程序只能检查覆盖，不能证明语义正确；严禁用自动按序配对取代语义判断。可先写译文和语义组（`whole: true` 或 `groups` 片段字符串），再跑 `pair-offsets ID --blocks groups.json --out aligned.json`。程序只在尚未占用的区间里独立定位每个片段（允许调序和交错；重复子串用 `occurrence` 或 `anchor` 消歧），不算语义，没有语义组时拒绝自动切分。`--out` 写入对齐结果，stdout 只返回 `path` 和 `block_count`。然后把文件交给 `assemble`。忠实保留数字、单位、引用、公式、否定和限定条件；作者疑点分开说明。每批 `translate` 提交就是检查点。可以只把 `[{id, translation}, ...]` 交给 `assemble ID translate --blocks blocks.json --submission-id ID --agent NAME --task tasks.json`，由它按这份读取时的 `tasks`/`show` 快照里的 revision 写成信封再 `submit`；它不用实时文档的最新 revision，也不生成译文。没有该快照时 assemble 报错。
6. 当前批次的译文哈希在默认 `show` / `tasks` 投影的 `blocks` 上（`translation_hash`）；引用壳上没有该字段，assemble 复核省略哈希时从同一快照 `blocks` 里同 id 的完整块补上，仍不用实时文档现算。要一次取全部块的哈希或 history 时用 `show ID --full`。第二轮从原文对照全部译文和术语，提交 `review`。把当时的 `tasks`/`show` JSON 交给 `assemble ID review --blocks blocks.json --submission-id ID --agent NAME --task tasks.json`。复核块可以省略 `translation_hash`，assemble 只从该快照里同 id 的块取哈希；你写的哈希会原样保留。没有快照，或快照里没有 revision / 对应 `translation_hash` 时，assemble 报错，不会静默改用最新文档。`note` 仍由你写，`submit` 仍拒绝空复核说明。用户在你读完任务之后若改了译文，旧快照上的 revision 和哈希会让 `submit` 因冲突或哈希不一致拒绝，未复核的新译文不会被标成已复核。`validate` 会检查数字、单位、引用和公式差异；合理换算须在对应块 `difference_explanation` 逐项解释，不能使用通用“差异可接受”掩盖错误。
7. `progress` 取当前全文 fingerprint（默认投影即含 fingerprint，不必拉取全量文档）。完成第二轮后 `full_review` 提交该指纹和复核说明。最后 `validate` 必须成功；完成状态仅代表流程与已记录检查通过，不等于原文内容真实或用户验收通过。按类已知限制不使 `validate` 失败，但会留在 `validate` 的 `warnings` 和 `confirmed_limitations` 里。默认 `progress` 只汇总类别、数量和样例，不把同一 resolution 与 evidence 重复数百次，也不把每条缺译/缺复核错误逐条展开；逐条内容看 `validate` 或 `progress --full`。成功的 `submit` 结果含 `revision`、`stage`、`pending_translate`、`pending_review`，通常不必在下一批前再调 `progress`。CLI 默认打印无缩进紧凑 JSON；需要给人读时加 `--pretty`。阅读页会标明这些限制仍然存在，完成不表示缺图、未编译插图等已经补上。
8. 默认 `export ID` 输出工作目录内单文件 HTML 并交付文件路径，不启动服务。仅有已知限制 warning 时导出仍可成功；快照沿用同一份 validation，读者在离线 HTML 里仍能看到这些限制，不要把导出说成资源已经补齐。仅在用户需要文献管理、修订或笔记时执行 `serve`。用户在网页修订、批注；你不得直接重写 `document.json` 或覆盖笔记。

## 中断、冲突与安全

- 换会话：重新读取此入口及 `tasks/progress`，只处理未完成项。
- 每次提交携带读取时的 `revision` 和唯一 `submission_id`。同 ID、同内容重试幂等；同 ID、不同内容拒绝。冲突时重新读取并核对差异，不能盲目改 revision 强行覆盖。
- 成功 `submit` 后按返回的 `stage` 与 `pending_translate` / `pending_review` 推进，不要在队列已经进入下一阶段时用同一批空转重交。失败重试沿用原来的 payload 与 `submission_id`；冲突则先重新读取并核对差异。
- 用户修订译文受保护，新的 Agent 翻译提交会拒绝该块；可以复核或给用户修改建议。术语用户修订同样受保护。
- 提交失败不会部分保存；禁止绕过 CLI 用编辑器改数据。笔记与阅读位置会增加文档版本，提交前应重新读最新状态。
- 全文 review 必须独立于 translate 的第二轮检查。不能批量写“已读”充当实际阅读。

字段、完整提交示例见 [数据格式](data-format.md)。

## 非论文文章

报告、技术文档与普通文章使用相同流程。保留原有标题、署名、日期、列表与引用，不补造摘要、方法或参考文献等论文结构。按实际语境解释关键表达；没有专业术语时提交空术语表。网页链接本身不是输入格式，需要提供本地文件（PDF / Markdown / txt / HTML 存档 / docx / 单文件 tex）。不抓取 URL，不做 OCR，不支持 EPUB。
